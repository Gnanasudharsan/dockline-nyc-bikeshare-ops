All notable changes to this project are documented here.
The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and
phases are tagged `phase-N` until the `v1.0.0` release.

## [Unreleased]

## [phase-5] — 2026-11-07

### Added
- FastAPI service (`api/`, port 8070), reading every metric from Cube:
  - `GET /v1/kpis/live`: network KPIs right now
  - `GET /v1/kpis/stream`: a Server-Sent Events update every 10 s
  - `GET /v1/stations/live`: stations with position and state, for the website map
  - `GET /v1/metrics`: the metric catalog
  - `POST /v1/ask`: Ask the Data
- Ask the Data (ADR 0018):
  - **How it works:** the LLM writes only a JSON plan over an allowlisted catalog;
    strict validation builds the Cube query. There is no SQL anywhere in the path.
  - **Defenses:** input limits, an injection screen, grounded answers (with a
    template fallback), and fixed refusal suggestions. Rate limits are 6 per minute per
    client and 500 per day.
  - **Responses** include the answer, metric definitions, the validated query, the rows,
    and data freshness.
  - **Providers:** Groq (default), Gemini, or Ollama.
- `evals/ask_the_data.jsonl` (40 cases), `evals/run_evals.py`, and a recorded live run.
  The live run scored 31/32 answerable (96.9%) and 8/8 refusals; CI replays it and
  enforces ≥ 85% and 100%.
- `make ask`, `make eval`, `make eval-live`. CI checks the API, the stream, and the
  stations endpoint in the stack.

## [phase-4] — 2026-11-07

### Added
- Power BI project `powerbi/Dockline.pbip`, generated as text by
  `powerbi/build_pbip.py` (ADR 0017):
  - TMDL semantic model with 8 DirectQuery tables and parameters `DbHost`, `DbPort`,
    `DbName`
  - 33 DAX measures with the same names as their Cube measures, in display folders
  - a `Date` table marked as the date table, sort-by columns, and 7 relationships

  - Dockline theme (`powerbi/theme/dockline.json`)
- dbt `bi` schema: Power BI-shaped views (local timestamps, integer keys, borough
  table). An integration test keeps them identical to the TMDL columns.
- Migration 0011: read-only `dockline_bi` login that can see only the `bi` schema.
- Validation without Power BI Desktop, also run in CI:
  - Microsoft's JSON schemas for every PBIR/PBIP file, at a pinned commit
  - Microsoft's report theme schema
  - every visual, sort, filter, relationship, and RLS field reference
  - TMDL parsed by Microsoft's `TmdlSerializer` (.NET 8 tool)
- `powerbi/VERIFY.md` (Desktop checklist, VM networking), `powerbi/BUILD_GUIDE.md`
  (with manual page specs), and the generated `powerbi/dax/measures.md`.
- `make powerbi`, `make powerbi-validate`, `make powerbi-reference` (Cube values to
  compare in Desktop).

## [phase-3] — 2026-11-07

### Added
- Cube Core semantic layer (`semantic/`): every catalog metric defined once across the
  `fleet_status` (live), `station_status`, `station_hourly`, `daily_kpis`, and
  `chronic_stations` cubes plus shared dimensions. Pre-aggregations in Cube Store for
  5-minute borough totals and hourly patterns (ADR 0015).
- Grafana OSS provisioned as code (`grafana/`):
  - datasources: Cube's SQL API for every metric (ADR 0014), and a read-only
    warehouse connection for annotations
  - dashboards, generated by `build_dashboards.py`: Live Network Overview, Station
    Drilldown, Rebalancing Board, Daily Review, and a public embeddable live dashboard
  - 10 s refresh, Dockline state colors, always labelled
  - time travel: history panels follow the time picker, and the map shows the network
    at the end of the range (ADR 0016)
  - alert rules as code: feed stale > 5 min, high-traffic station empty > 10 min,
    ingestion runs failing
  - Dagster pipeline events annotated on every dashboard
- `live_dbt_build` Dagster job: the 5-minute grid and fact rebuilt every 5 minutes, so
  rewind data is never more than about 10 minutes old.
- `mart_rebalancing_recommendations` gains `minutes_empty` and `is_high_traffic`.
- Migration 0010: read-only `dockline_reader` role for Cube and Grafana. The migrate job
  sets its password from `.env`.
- `scripts/init_env.py` (`make env`): creates or updates `.env` and generates random
  local passwords and secrets.
- `grafana/check_dashboards.py`: runs every panel query through Grafana (also in CI).
  `grafana/test_stale_feed_alert.sh` checks that the stale-feed alert fires.
- Tests for the semantic layer (catalog coverage, ratio construction) and Grafana
  provisioning (dashboards match the builder, Cube-only panels, alert thresholds).
- `make grafana-dashboards`, `make check-grafana`, `make grafana-public`,
  `make test-stale-alert`.

### Changed
- Grafana listens on port 3060, leaving 3000 for the website.

## [phase-2] — 2026-11-07

### Added
- dbt project (`dbt/`): sources with freshness rules; staging views; seeds for NYC 2020
  neighborhood polygons, GBFS regions and WMO weather codes.
- Station placement by borough and neighborhood using core Postgres `polygon`
  operators, with no PostGIS (ADR 0011).
- `int_station_status_5min_filled`: an incremental station × 5-minute grid that carries
  each station's last report forward. Incremental and full-refresh runs produce
  identical rows (ADR 0010).
- Star schema:
  - dimensions: `dim_station` (SCD2 from `snap_stations`), `dim_date`, `dim_time`,
    `dim_weather`
  - facts: `fct_station_status_5min`, `fct_station_hourly`, `fct_daily_kpis`
  - snapshot: `snap_daily_kpis`, the as-of history of daily KPIs (ADR 0013)
- Operations marts: `mart_rebalancing_recommendations`, a live view, and
  `mart_chronic_stations`.
- dbt tests: 80+ data tests (dbt-utils, dbt-expectations) and dbt unit tests for the
  carry-forward and placement logic. SQLFluff linting.
- Dagster code location (`orchestration/`):
  - dbt assets grouped by layer, with the raw tables as external roots
  - schedules: hourly and daily dbt builds, and raw freshness checks every 5 minutes
  - freshness policies on marts
  - a run-failure sensor
  - alerts written to `ops.pipeline_events` (migration 0009) for Grafana annotations
    (ADR 0012)
- `dagster-webserver` (port 3070) and `dagster-daemon` Compose services. Their run
  storage is a `dagster` database created by the migrate job.
- Integration tests that run the full `dbt build` on hand-built data and assert exact
  results, plus the alert and freshness-check paths.
- CI:
  - SQLFluff and `dbt parse`
  - `dbt build` inside the orchestration image on live data
  - a check that Dagster loads with all schedules running
- `docs/metrics.md` (metrics catalog), `make dbt-build`, `make dbt-docs`,
  `make dbt-freshness`, `make dagster-dev`, `make check-pipeline`.

### Changed
- The ingestion image installs only the ingestion and warehouse packages.

## [phase-1] — 2026-11-07

### Added
- Ingestion service (`ingestion/`): async poller for GBFS `station_status` (every feed
  ttl), `station_information` (hourly) and Open-Meteo hourly weather. GBFS feeds are
  resolved through auto-discovery, preferring v2.3. Per-record Pydantic v2 validation
  with counted rejection reasons, idempotent `unnest` batch writes, tenacity retries
  with jittered backoff, graceful SIGTERM shutdown, heartbeat healthcheck, JSON logs.
- Warehouse migrations (`warehouse/`): `raw.station_status` hypertable (unique on
  `station_id, last_reported`, compressed after 7 days, dropped after 30),
  `raw.station_information`, `raw.weather_hourly`, `ops.ingestion_runs` audit log, and
  5-minute and hourly continuous aggregates kept forever.
- In-house migration runner with checksums, advisory locking and no-transaction
  support, run as the one-shot `migrate` Compose service.
- Unit tests on recorded feed fixtures and end-to-end integration tests against a
  throwaway TimescaleDB container (testcontainers).
- CI: integration tests, plus a live smoke test that builds the stack and checks that
  real GBFS rows land.
- `make migrate`, `make psql`, `make test-unit`, `make check-ingestion`.
- ADR 0006 (raw status storage model) and ADR 0007 (migration runner).

### Fixed
- station_status polls are scheduled from the feed's `last_updated + ttl` instead of
  a fixed 60 s timer, which could phase-lock just before each feed refresh and miss
  a version (found during the acceptance run; ADR 0008).
- station_status uses ETag conditional requests, so checks for a new version return
  an empty 304 instead of re-downloading an unchanged payload. Runs record
  `not_modified` (migration 0008, ADR 0009).

  Grafana, Power BI, API, web, infra and docs.
- Docker Compose skeleton with a TimescaleDB 2.31 (PostgreSQL 16) service, healthcheck,
  restart policy and resource limits; Postgres bound to localhost by default.

  gitleaks, YAML/JSON checks).
- Makefile with `setup`, `up`, `down`, `test`, `lint`, `logs`.
- Repository hygiene tests that enforce healthchecks, restart policies, resource
  limits, and that every Compose variable is documented in `.env.example`.
- GitHub Actions CI: lint, type-check, test, secret scan, Compose validation.
- `CLAUDE.md` project spec, ADRs 0001–0005, MIT license.
