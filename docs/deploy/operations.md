# Operations

All commands run on the VM, from the repository directory.

## Daily glance

- **Status:** `make prod-ps` (every service `healthy`).
- **Dashboards:** Grafana's Live Network Overview shows data age; alert rules fire when
  the feed is stale for more than 5 minutes, ingestion runs fail, or a high-traffic
  station is empty for more than 10 minutes. Runbooks: `grafana/README.md`.
- **Pipelines:** Dagster (through the SSH tunnel) shows the live, hourly, and daily dbt
  runs and freshness. Failed runs are also written to `ops.pipeline_events` and shown on
  Grafana.
- **Uptime:** the GitHub **Uptime** workflow emails you when the public API, the data
  freshness, or the website check fails.

## Logs

```bash
docker compose -f docker-compose.yml -f infra/docker-compose.prod.yml logs -f --tail=200 ingestion api
```

Docker rotates logs: in production each container keeps at most 5 × 20 MB (json-file
driver, `infra/docker-compose.prod.yml`). All services log JSON.

## Backups and restores

- **Nightly backups:** the `backup` service dumps the warehouse and Dagster databases at
  03:30 New York time into `BACKUP_PATH` (`./backups` by default).
  - `daily/`: the last 7 dumps.
  - `weekly/`: the last 4 Sunday dumps.
  - Its healthcheck turns unhealthy if no backup has succeeded in 26 hours.
- **Back up now:** `make backup-now`.
- **Test a restore monthly.** The restore script always creates a new database and never
  touches the live one:

  ```bash
  docker compose -f docker-compose.yml -f infra/docker-compose.prod.yml run --rm --no-deps --entrypoint /scripts/restore.sh backup /backups/daily/<file>.dump dockline_restore_check
  ```

  It prints row counts; compare them with the live database. Then drop the check
  database:

  ```bash
  docker compose exec timescaledb psql -U dockline -d postgres -c 'DROP DATABASE dockline_restore_check'
  ```

- **Off-site copies:** the dumps live on the VM's disk. For off-site copies, sync
  `backups/` to free object storage (for example Oracle Object Storage, with 20 GB in
  the free tier) with `rclone` on a cron job.

## Upgrades

```bash
git pull
```
```bash
make prod-up
```

Images are rebuilt and the `migrate` job applies any new migration before ingestion
starts. Dagster reloads the new dbt manifest automatically. To roll back:

```bash
git checkout v1.0.0 && make prod-up
```

If a migration changed data, restore the last backup into a new database first and
compare.

## Rotating secrets

1. Change the value in `.env`:
   - `DOCKLINE_READER_PASSWORD`, `DOCKLINE_BI_PASSWORD`, `CUBEJS_*`, and
     `GRAFANA_ADMIN_PASSWORD` can be regenerated by deleting the line and running
     `make env`.
   - API keys and the tunnel token are pasted in.
2. Run `make prod-up`. The migrate job re-applies role passwords on every start.
3. `POSTGRES_PASSWORD` is the database superuser's password. Change it inside Postgres
   first, then in `.env`:

   ```sql
   ALTER ROLE dockline PASSWORD '...';
   ```

## Disk

The data uses about 2–3 GB in steady state:
- raw station reports: 30 days (compressed after 7 days)
- continuous aggregates and hourly and daily facts: kept forever and small
- 5-minute facts: 35 days
- backups: up to 11 dumps

Check usage with `docker system df` and `du -sh backups`.
