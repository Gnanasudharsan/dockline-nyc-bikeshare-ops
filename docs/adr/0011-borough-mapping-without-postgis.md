# 0011. Place stations in boroughs and neighborhoods without PostGIS

- Status: Accepted
- Date: 2026-11-07

## Context
Borough and neighborhood are required dimensions. GBFS gives coordinates and a
`region_id` (NYC District, JC District, Hoboken District, ...), but not boroughs. The
TimescaleDB image has no PostGIS, and adding it would mean a custom image for one join.

## Decision
- Seed NYC's 2020 Neighborhood Tabulation Areas (NYC Open Data `9nt8-h7nd`), simplified
  to ~20 m with shapely and stored as core Postgres `polygon` literals
  (`dbt/seeds/nyc_neighborhoods.csv`, 240 KB, regenerated by
  `dbt/scripts/build_neighborhood_seed.py`).
- Match with built-in geometric operators: `polygon @> point` (contains) and
  `polygon <-> point` (distance). Order of precedence:
  1. GBFS region with a fixed borough (Jersey City, Hoboken);
  2. containing NTA polygon;
  3. nearest NTA polygon within ~500 m (piers and shoreline);
  4. nearest already-placed station within ~1 km (a few NJ stations have no region);
  5. `Unknown`.
- Record which rule placed each station in `location_method`.

## Consequences
- All 2,520 current stations are placed; 3 Hoboken stations use rule 4.
- Simplification can move a station across a neighborhood boundary within ~20 m;
  borough assignment is unaffected in practice.
- Distances are in degrees, not meters. The thresholds are small enough that the
  latitude distortion (~0.76 at NYC) does not matter.
